# MirthSpool v0.1.4

This security release publishes the repository and application hardening work,
the reviewed iFunny connector, and the follow-up CodeQL remediations on the
rewritten public history.

## Install and verify

Follow [the installation guide](../INSTALL.md) and use only the immutable
`ghcr.io/...@sha256:` references attached to this release. The workflow builds
and scans the web and worker images, publishes per-image SPDX SBOMs, and creates
GitHub build-provenance attestations tied to this tag.

## Migration and rollback

Run the documented migration deployment command before starting v0.1.4. This
release adds the forward-only `20260728233000_ifunny_source` migration. Rollback
remains restore-from-verified-backup; retain the database backup and separately
escrowed `APP_ENCRYPTION_KEY` before upgrading.

## Security notes

- First-administrator setup requires a single-use high-entropy setup token.
- Production secrets, database credentials, origins, proxy assertions, and
  private-source allowlists are validated at startup.
- Authentication payloads are bounded before hashing or authentication work.
- Worker egress is separated from the internal PostgreSQL/Redis network.
- Repository history and the current tree are scanned independently for
  secrets and forbidden artifacts.
- CodeQL, production dependency auditing, and HIGH/CRITICAL container scans are
  required checks.

Existing clones and forks of pre-rewrite history are outside the repository
owner's control and should be replaced with a fresh clone.

## Known limitations

- Release images target `linux/amd64`.
- TLS and reverse-proxy lifecycle remain operator-owned.
- PostgreSQL rollback is restore-based rather than down migrations.
- Private destinations remain denied unless explicitly reviewed and allowlisted.
