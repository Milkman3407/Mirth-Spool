# MirthSpool v0.1.3

This patch release preserves the reviewed M00–M17 product scope while fixing
the final release metadata export for mixed-case GitHub owner names. Image
repository references are now normalized to lowercase before Docker inspection,
provenance, and artifact generation. It also retains the v0.1.2 browser-test
fixes: host packages are built before Playwright runs, Chromium is installed
from the root workspace, and the intentional failing fixture uses a distinct
network origin so circuit-breaker state cannot leak between serial scenarios.

## Install and verify

Use [the installation guide](../INSTALL.md) and deploy the `@sha256:` references
attached to this GitHub release. The release workflow also attaches per-image
SPDX JSON SBOMs; OCI manifests carry maximum-mode BuildKit provenance/SBOM
attestations, and GitHub publishes verifiable build-provenance attestations.

## Migration and rollback

There is no v0.1.3 schema migration. A new install applies all ten forward-only
migrations through `20260723150000_deduplication_search_filters`. An upgrade
from v0.1.2 uses the same idempotent deployment command before starting v0.1.3.
Follow [the upgrade and rollback guide](../UPGRADE.md); after a migration,
rollback is restore-from-verified-backup rather than down SQL.

## Known limitations

- Only `linux/amd64` release images are tested and published.
- MirthSpool is a private single-instance application, not a hosted SaaS or
  multi-tenant platform. TLS and reverse proxy lifecycle remain operator-owned.
- Manual meme upload is intentionally absent.
- RSS/Atom, Lemmy API v3, public Mastodon-compatible timelines, and approved
  Reddit OAuth Data API are the only ingestion surfaces. There is no HTML
  scraping or restriction bypass.
- Remote media reveals client network metadata to its provider; caching changes
  that tradeoff but consumes bounded server storage. Unknown ratings remain
  explicit and policy-controlled.
- PostgreSQL rollback is restore-based. Source credentials cannot be recovered
  without the separately escrowed `APP_ENCRYPTION_KEY`.
- Screenshots are omitted to avoid creating a misleading production-data
  example; all automated fixtures and acceptance data are synthetic.
- M18 invitation-based multi-user support and M19 recommendation/discovery work
  are explicitly deferred and are not part of v0.1.3.

## Security notes

Review release SBOMs and scan results before deployment. Images run as non-root
with read-only filesystems, dropped capabilities, private service networking,
and explicit CPU, memory, and process bounds. Configuration contains no safe
default for secrets. PostCSS is pinned to patched version 8.5.12; the production
dependency audit has no high or critical findings. Connector traffic remains bounded and SSRF-filtered; Reddit
access requires the operator's own approved credentials.
