# MirthSpool v0.1.5

This patch release corrects the production-parity release acceptance harness
that blocked v0.1.4 before any image or GitHub release was published.

## Install and verify

Follow [the installation guide](../INSTALL.md) and use only the immutable
`ghcr.io/...@sha256:` references attached to this release. The workflow builds
and scans the web and worker images, publishes per-image SPDX SBOMs, and creates
GitHub build-provenance attestations tied to this tag.

## Migration and rollback

Run the documented migration deployment command before starting v0.1.5. The
forward-only `20260728233000_ifunny_source` migration remains the newest schema
change. Rollback remains restore-from-verified-backup; retain the database
backup and separately escrowed `APP_ENCRYPTION_KEY` before upgrading.

## Security notes

- Production runtime validation remains strict: the declared public origin
  must use HTTPS.
- The acceptance harness models external TLS termination while reaching the
  loopback-published container port directly.
- Failed acceptance runs emit bounded service diagnostics before cleanup.
- CodeQL, production dependency auditing, secret scanning, and HIGH/CRITICAL
  container scans remain required release gates.

## Known limitations

- Release images target `linux/amd64`.
- TLS and reverse-proxy lifecycle remain operator-owned.
- PostgreSQL rollback is restore-based rather than down migrations.
- Private destinations remain denied unless explicitly reviewed and allowlisted.
